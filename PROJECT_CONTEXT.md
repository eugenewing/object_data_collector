PROJECT CONTEXT

Язык: русский
Файлы проекта (пути и назначение):
- ObjectDataCollector_ver.1.0.0.mq4
  - Основной файл советника. В нём реализуется GUI-логика, обработка нажатий клавиш, кликов мыши, создание графических объектов (трендлинии и прямоугольники), лейбл режима и кнопка для запуска сбора данных. Код писать в стиле Java (ясная структуризация, отступы, говорящие имена переменных/функций).
- AndyFunc_ver.1.0.0.mqh
  - Включаемый файл. В нём должны быть вынесены пользовательские функции для сбора данных с объектов. Все пользовательские функции должны иметь префикс a_ и располагаться в конце файла, после комментария: "Раздел с функциями".

Краткое описание функционала советника:
- Поддерживаемые формации (4 типа):
  1) Тренд (trend) — рисуется как трендовая линия (двухточечная линия без свойства "луч"), фон.
  2) Импульс (impulse) — рисуется как трендовая линия (двухточечная линия без свойства "луч"), фон.
  3) Паттерн продолжения (pattern_continuation) — рисуется прямоугольником, фон.
  4) Паттерн разворота (pattern_reversal) — рисуется прямоугольником, фон.

- Привязка к клавишам:
  - 1 → формация 1 (тренд)
  - 2 → формация 2 (импульс)
  - 3 → формация 3 (паттерн продолжения)
  - 4 → формация 4 (паттерн разворота)

- Процесс рисования (интерактив):
  - Пользователь удерживает одну из клавиш 1..4, делает два клика мышкой по графику (первый и второй клик привязываются к двум барам).
  - По второму клику советник создаёт соответствующую формацию между двумя барами.
  - Временные координаты объекта = время двух баров, соответствующих кликам (бар1, бар2).
  - Ценовые координаты (в зависимости от типа и направления):
    * Тренд вверх: цены = Low(bar1), Low(bar2)
    * Тренд вниз: цены = High(bar1), High(bar2)
    * Импульс вверх: цены = Low(bar1), High(bar2)
    * Импульс вниз: цены = High(bar1), Low(bar2)
    * Паттерны (оба типа): цена верх = max High в диапазоне бар1..bar2, цена низ = min Low в диапазоне бар1..bar2

- Визуальные свойства объектов:
  - Все объекты рисуются как фон (OBJPROP_BACK = true).
  - Тренд и импульс имеют разные цвета между собой.
  - Паттерн продолжения и паттерн разворота имеют разные цвета между собой.
  - Имя объекта должно быть формируемым (префикс + тип + timestamp/счётчик) для уникальности.

- Лейбл режима рисования:
  - Всегда присутствует скрытый в списке объектов и нередактируемый объект-лейбл.
  - Лейбл показывает текущий режим рисования (какая формация активна) когда пользователь удерживает одну из клавиш.
  - Расположен в правом нижнем углу графика.

- Кнопка "Собрать данные":
  - На графике есть кнопка для запуска сбора данных (скрыта в списке объектов и нередактируемая).
  - Кнопка располагается в правом верхнем углу графика.
  - По нажатию кнопки запускается процедура сбора данных и записи в CSV.

- Сбор данных (поля и правила):
  Для каждой формации (объекта) сохраняются поля:
  - имя объекта
  - тип формации (тренд / импульс / паттерн продолжения / паттерн разворота)
  - дата начала формации (дата бара1)
  - время начала формации (время бара1)
  - дата окончания формации (дата бара2)
  - время окончания формации (время бара2)
  - высота формации в пунктах (разность верх-низ с учётом пунктов для символа)

- Настройки советника:
  - 4 булевых входных параметра (bool) для включения/отключения сбора данных по каждому из 4 формаций.
  - Параметры файла CSV (путь/имя) — будут согласованы перед реализацией; по умолчанию можно использовать папку данных терминала или заданный в проекте путь.

Кодовые соглашения / требования:
- Стиль кода «в стиле Java»: четкая структура, явные имена функций и переменных, комментарии, пары открывающих/закрывающих блоков, аккуратные отступы.
- В AndyFunc все пользовательские функции для сбора данных должны иметь префикс a_ и находиться в конце файла после комментария "Раздел с функциями".
- Обновления кода в существующих файлах будут выполняться по шагам из NEXT_STEPS, каждый шаг согласовывается с заказчиком перед выполнением.

Ограничения / дополнительные требования:
- Все создаваемые вспомогательные объекты (лейбл, кнопка) должны быть скрыты в списке объектов и нередактируемы.
- Использовать стандартные MQL4 объекты: OBJ_TREND, OBJ_RECTANGLE, OBJ_LABEL, OBJ_BUTTON. Создать имитируемую кнопку через лейбл/графический объект если объект "кнопка" отсутствует в нужной версии.
- При реализации функций сбора данных учитывать специфику символа (Digits) для перевода в пункты (points/pips).

Следующие шаги и рабочий процесс описаны в файле NEXT_STEPS.md. Выполнять шаги NEXT_STEPS строго по одному и перед выполнением каждого следующего шага согласовывать план действий с заказчиком.
